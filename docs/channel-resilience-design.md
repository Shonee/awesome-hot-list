# 渠道韧性与展示策略设计

## 目标

- 渠道采集、首次展示、综合报告参与三种行为独立配置。
- 官方结构化数据优先，稳定第三方页面作为第二级降级；RSS 只能进入 RSS 聚合卡片。
- 福利吧定时采集但默认隐藏，并默认排除在综合报告之外。
- 脉脉在缺少稳定免登录来源时不参与默认采集和展示。
- 对今日热榜等共享第三方来源实施进程级缓存和请求间隔控制。

## 数据流

普通渠道遵循 `官方 -> 第三方 -> stale 快照`。Ranking 的 `sourceUrl` 保持目标
榜单地址，`providerName/providerUrl` 记录实际数据提供方。RSS 降级不生成原渠道
快照，而是作为 RSS 快照内的一个 ranking。

`ChannelDefinition` 保留 `enabled_by_default` 作为定时采集开关，新增
`visible_by_default` 和 `include_in_report`。这样不会破坏现有 CLI 和工作流参数，
同时避免默认隐藏渠道污染报告覆盖率与热点聚类。

## 兼容性

页面偏好增加版本号。首次读取旧版 localStorage 时，仅把新策略中默认隐藏的渠道
重置为隐藏，保留主题、布局、排序和 RSS 设置；迁移后用户手动开启的选择会继续保存。

## 风险控制

- 第三方请求默认至少间隔 3 秒，同一运行进程内相同 URL 只请求一次。
- 解析器设置最小有效条数，空页面不会覆盖成功快照。
- 新字段保持 JSON 向后兼容，旧快照和旧报告仍可渲染。
- 福利吧内容默认隐藏且不进入报告，以隔离敏感或垂直内容。
