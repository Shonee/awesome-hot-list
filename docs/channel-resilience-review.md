# 渠道韧性与报告优化审查

## 审查结论

本轮实现符合已确认的渠道归属、默认展示、报告排除和第三方限频要求，未发现阻塞交付的问题。

## 已关闭问题

- 今日与历史报告均消费跨日比较，展示新增、升温、降温、持续和掉榜信号，升降榜带前后名次。
- 综合热度不再使用绝对名次或严格词典序评分，统一结合跨渠道覆盖、榜单百分位、持续度和新鲜度。
- 新增按渠道采集频率计算的 `samplingCoverage`，页面对旧报告继续回退到 `coverage`。
- RSS 单 Feed 失败通过快照 `warnings` 显示在渠道状态提示中，其他成功 Feed 可继续更新；全部失败才返回渠道级错误。
- 390px 视口下顶部导航与设置入口均在页面范围内，卡片完整展示 10 条且没有内部纵向滚动。

## 剩余风险

- 官方页面和 TodayHot HTML 结构仍可能变化，需要依靠最小条数校验、失败降级和 stale 快照降低影响。
- Linux.do RSS 在部分本地网络出现 TLS EOF，最终可用性仍应以 GitHub Actions 运行网络为准。
- TodayHot 限频是进程级策略；两个定时工作流使用同一并发组并错开 16 分钟，可避免自动任务并发请求，但人工在其他环境并行启动多个进程时仍需自行控制频率。
