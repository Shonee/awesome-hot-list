# 热榜内容面与 7x24 优化代码审查

## 审查结论

未发现阻断交付的关键或主要问题。实现符合已确认的产品约束：不新增顶层 Tab，7x24 嵌入来源卡片，RSS 退役，本地宝不接入，Readhub/央视/外交部不进入综合报告。

## 重点检查

- 数据契约：`Ranking.surface` 同时进入 JSON 和 CSV，报告只处理 `hotlist`。
- 高频采集：`--surface live` 下推到专用适配器，新浪和财联社不会先请求普通榜单；局部合并保留同卡片既有榜单。
- 时间窗口：默认最近 3 小时；超过 100 条改取最近 1 小时；仍超过时保留最新 100 条。
- 必应迁移：只接受 `domestic-trending`，旧 `trending-news` 国际版快照立即隐藏；国内旧快照失败后最多展示 24 小时。
- RSS 退役：注册表、工作流环境变量、网络探测、页面控件和报告链路均已移除；适配器源码与历史数据保留。
- 页面加载：普通 JSON 请求使用浏览器默认缓存，只有手动重试使用 `cache: reload`。
- 分层加载：`latest.json` 先载入，`live/digest/authority` 在空闲时并行合并；卡片用稳定高度占位和 `IntersectionObserver` 渐进挂载。
- DOM 预算：首批卡片按实际 HTML 节点数计算，首次滚动前观察器也不得突破 1500；滚动后恢复 640px 提前挂载。
- 采集/报告解耦：所有采集 CLI 只写归档与分面快照，报告由每小时独立渲染任务统一生成。
- 渠道目录：39 个渠道均有版本化全量记录，CI 检查运行时真值，并支持可回放的 `add/remove/replace` 增量链。
- 性能：标题聚类使用 bigram 倒排候选；日终渲染对今日、昨日和前日各读取、构建一次。

## 性能与架构扫描

- 扫描范围：`src/` 与 `tests/` 的 Python/JavaScript 关键路径。
- 循环内网络请求候选均为固定小集合：Readhub 3 个栏目、AcFun 3 个榜单、Hacker News 最多 25 个详情，不属于无上限 N+1。
- 未发现数据库查询、无上限全量拉取、无限全局缓存或高并发请求线程中的同步文件 I/O。
- 标题聚类从全量两两比较改为 bigram 候选索引；500 个互不相关标题的测试中，相似度比较少于 500 次，朴素实现最多需要 124,750 次。
- live 专用入口将新浪每轮请求从 3 个端点降到 1 个，减少约 67%；财联社从 2 个降到 1 个，减少 50%。
- 日终渲染的基础报告读取/构建从 4 次降到 3 次，减少 25%，并消除昨日数据重复处理。

自检结果：无新增 O(n²) 关键路径；外部请求均有超时、有限重试和渠道级失败隔离；数据分支写入由统一并发组串行化。当前规模下继续引入异步框架或持久缓存收益有限，不建议过度优化。

## 验证证据

- Python 单元测试：208 项通过。
- Node 页面行为测试：7 项通过。
- Python 编译、`git diff --check`：通过。
- GitHub Actions YAML：9 个文件解析通过。
- 真实 `data-pages` 副本渲染：14.08 秒；`latest.json` 原始 587,197 字节、gzip 173,963 字节，低于 300 KiB 预算。
- 浏览器验收：1440x900 桌面首屏 1417 个 DOM 节点，390x844 移动端 1484 个；滚动挂载、补充内容面合并和无横向溢出均通过。
- 渠道目录一致性、旧合并快照自动迁移、四个内容面分流检查：通过。
- 真实 live CLI：新浪 50 条、财联社 20 条、华尔街见闻 42 条。
- 真实网络探测：Readhub 47 条、央视 6 条、外交部 30 条；必应本机返回 0 条，按可选探测处理。
- 本地静态页：HTTP 200，模板无 RSS 标识，旧国际版必应迁移逻辑存在并通过行为测试。

## 剩余风险

- 必应中文首页热点依赖地区与页面结构，本地未取得有效条目；需要在 GitHub Actions runner 中继续观察，失败时不会回退国际版。
- Readhub、央视、外交部和三个 7x24 来源均为外部 HTML/API，结构变更仍可能导致单源采集失败；失败隔离不会中断其他渠道。
- 本轮没有提交、推送、手动触发远端工作流或部署，15 分钟 cron 的远端运行效果尚未验证。
